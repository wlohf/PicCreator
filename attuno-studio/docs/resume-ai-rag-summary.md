# Attuno Studio 简历项目总结

## 项目定位

Attuno Studio 是一个面向室内设计场景的 AI 对话与图像生成工作台，采用 FastAPI + React/Vite + TypeScript 架构。项目将日常对话、联网检索增强、提示词编排、图像生成/编辑、多模型供应商配置、账号级记忆与资产管理整合到同一个工作流中。

## 简历一句话

独立开发 AI 室内设计工作台 Attuno Studio，构建多模型适配、联网检索增强、账号级记忆、图像生成编辑和多用户数据隔离能力，支持从自然语言需求到检索增强对话、提示词编译、效果图生成、结果续改和资产管理的完整 AI 应用闭环。

## 技术栈

- 前端：React, TypeScript, Vite
- 后端：FastAPI, Python, Pydantic
- AI 能力：LLM 对话、流式输出、联网检索增强、提示词编译、视觉分析、图像生成、图像编辑
- 模型适配：OpenAI Chat/Responses, OpenAI Images API, Gemini, Anthropic, Azure OpenAI, Ollama, OpenAI-compatible 自定义接口
- 数据与状态：账号级配置文件、本地持久化、会话历史、结果资产、用户偏好与记忆
- 工程化：pytest, TypeScript build, 前端静态测试脚本, Trellis 任务/规范工作流

## 核心功能

### AI 对话与 RAG/检索增强

- 实现聊天优先的 AI 工作区，支持日常对话、需求澄清、图像草稿生成建议和流式输出。
- 基于用户搜索意图触发联网检索，将 Tavily/DuckDuckGo 搜索结果注入 LLM system context，返回结构化 `web_search` 元数据。
- 实现账号级 Tavily 多 key 轮询能力，支持 key 去重、持久化轮询指针、失败切换和 DuckDuckGo fallback，避免不同账号共享 key 池。
- 聊天链路区分普通咨询和图像生成意图，避免 logo 命名、风格讨论等普通问题误触发图像生成。

### 多模型与供应商配置

- 设计分析/聊天模型与图像模型的多供应商档案系统，每个档案保存 provider、API format、Base URL、API Key 和模型名。
- 支持 OpenAI、Responses、Gemini、Anthropic、Azure OpenAI、Ollama、OpenAI-compatible、Images API 等多种协议。
- 实现模型检测、连接验证、活动供应商切换、非活动供应商 key 保留和账号级配置隔离。
- 登录用户不会继承 default 工作区密钥，降低多用户部署时的 key 泄露风险。

### 图像生成与编辑工作流

- 支持 `standard` 文本/参考图生成、`render3d` 平面图转 3D 效果图、`colored_floor_plan` 彩色平面图工具动作。
- 实现平面图解析、空间结构约束提取、提示词编译、可选严格复核和多模型失败切换。
- 支持结果续改、参考图编辑、标注续改、图片复制、下载、结果笔记和历史资产管理。
- 实现 A/B 图片对比分析，可从当前聊天和图片库选择对比对象。

### 账号、记忆与资产隔离

- 实现账号注册/登录、session cookie 鉴权和账号级数据目录。
- 聊天历史、生成结果、API Key、供应商配置、快捷短语、自定义提示词模式、偏好和记忆均按账号隔离。
- 设计手动确认的记忆写入机制，区分日常聊天记忆、生图长期偏好、避免项、项目偏好和评判标准。
- 前端本地缓存仅作为账号级迁移/恢复补充，后端账号数据是可部署形态下的主数据源。

### 前端产品体验

- 构建聊天工作区、图像工作区、设置弹窗、模型配置、提示词模式管理、图片管理和记忆面板。
- 支持流式对话中断、按会话维度的响应状态、历史会话恢复、重试版本、分支对话和图片消息展示。
- 配置页支持多 provider 档案、API key 显示/隐藏、模型搜索、Tavily key textarea 和账号级保存。

## 可放简历的项目经历版本

### 版本 A：AI 应用开发方向

**Attuno Studio - AI 室内设计对话与图像生成工作台**

- 独立设计并实现 FastAPI + React/TypeScript 全栈 AI 应用，支持账号体系、模型配置、聊天工作区、图像生成工作区、结果资产管理和用户记忆。
- 构建多模型适配层，兼容 OpenAI Chat/Responses、OpenAI Images API、Gemini、Anthropic、Azure OpenAI、Ollama 和自定义 OpenAI-compatible 接口，支持分析模型与图像模型多供应商档案切换。
- 实现自然语言到图像生成的完整链路：需求理解、平面图解析、提示词编译、参考图生成、3D 效果图生成、图片续改、标注编辑和 A/B 对比分析。
- 设计多用户数据隔离方案，将聊天历史、生成结果、API Key、模型配置、提示词模板和长期记忆按账号命名空间持久化，避免默认工作区密钥泄露。
- 建立 pytest 与 TypeScript build/静态测试验证流程，覆盖配置持久化、账号隔离、联网搜索、聊天 API 和图像工作流关键路径。

### 版本 B：RAG/检索增强方向

**Attuno Studio - 支持联网检索增强的多模型 AI 工作台**

- 在 AI 对话链路中实现检索增强模块，基于用户显式搜索意图触发 Tavily/DuckDuckGo 联网搜索，并将结构化搜索结果注入 LLM system context。
- 设计账号级 Tavily key 池与轮询机制，支持多 key 规范化、去重、持久化轮询指针、失败自动切换和无 key 时 DuckDuckGo fallback。
- 保持搜索结果元数据 `query/results/ok` 贯穿普通响应与 SSE 流式响应，便于前端展示检索状态和后续扩展来源引用。
- 将检索增强与多模型供应商配置、账号鉴权、聊天历史、用户记忆和图像生成工作流结合，形成可部署的 AI 应用闭环。
- 编写回归测试覆盖 key 归属隔离、轮询顺序、失败切换、fallback 和前端配置序列化，确保检索增强能力在多用户场景下稳定运行。

## 面试可讲亮点

- 不是单纯调用大模型 API，而是做了模型适配、配置管理、账号隔离、检索增强、提示词编排、流式交互和结果资产管理的完整产品化工程。
- RAG 部分采用“搜索意图识别 -> 搜索 provider -> 结构化结果 -> system context 注入 -> 响应元数据返回”的链路，后续可扩展为向量知识库、来源引用和多检索源融合。
- Tavily key 轮询使用用户命名空间持久化指针，解决多账号场景下 key 池共享、额度串用和进程重启丢失轮询状态的问题。
- 图像生成部分将空间结构分析、提示词编译、模型兼容性判断和多模型 fallback 组合起来，降低单一模型失败对用户工作流的影响。
- 账号级长期记忆采用手动确认写入，避免普通聊天内容无感进入长期记忆，兼顾个性化和可控性。

## 可继续强化的方向

- 将当前联网搜索扩展为真正的知识库 RAG：文档上传、切片、embedding、向量检索、重排和引用展示。
- 增加 search/source citation UI，把 Tavily/DuckDuckGo 来源以引用卡片形式展示在聊天回复中。
- 对 key 池增加健康状态、失败次数、冷却时间和使用统计。
- 将配置文件持久化升级为 SQLite/PostgreSQL，进一步增强并发写入和部署可靠性。
- 增加 E2E 测试覆盖登录、配置、搜索增强聊天、图像生成和结果续改完整用户路径。
