# Attuno 需求文档

> 最后核对：2026-07-11  
> 状态：当前已交付能力基线。实时发布状态以 [项目进度](project-status.md) 为准。

## 1. 产品定位

Attuno 是面向室内设计场景的 AI 对话与图像辅助工作台。它不是单一的“输入提示词后出图”页面，而是把设计需求、平面图、参考图、用户偏好、图像生成和后续修改串成可重复使用的工作流。

目标用户包括室内设计师、设计团队成员，以及需要从空间需求快速获得设计方向、效果图和修改记录的业务用户。

## 2. 核心用户流程

```text
登录或进入账号工作区
  -> 日常聊天梳理需求、查询资料或形成设计草稿
  -> 切换图像工作区，选择生图模式并补充平面图/参考图
  -> 生成结构优先的提示词并调用图像模型
  -> 查看结果、笔记、来源与评估信息
  -> 继续编辑、标注改图或 A/B 对比
  -> 选择性保存偏好、快捷短语和自定义提示词模式
```

## 3. 已交付能力

### 3.1 聊天与设计辅助

* 常规聊天、流式输出、中断控制和聊天分支/历史恢复。
* 设计助手可识别聊天、结构修改、家具修改、风格修改、结果分析和偏好记忆等意图。
* 对时效性或第三方事实类问题，可按规则和模型决策触发联网检索。
* 聊天支持图片附件；前端会避免向不支持视觉输入的模型发送图片上下文。
* 历史首屏采用本地快速恢复、服务端摘要列表和单会话按需加载，降低完整历史阻塞。

### 3.2 图像生成与编辑

* `standard` 文生图/参考图生成。
* `render3d` 平面图感知的 3D 空间效果图流程。
* 彩色平面图作为显式工具动作保留。
* 自定义图像提示词模式；模板支持 `{prompt}` 与 `{{prompt}}` 占位符。
* 结果续改、源图编辑、标注编辑、生成请求取消和 A/B 比较分析。
* `render3d` 使用结构优先的 Prompt Compiler：墙体、门窗、固定结构、房间用途和家具拓扑优先于风格装饰。

### 3.3 用户配置、资产与记忆

* 注册、登录、会话 Cookie 与账号级数据隔离。
* 分析/聊天模型和图像模型分别支持多个供应商档案。
* 支持 OpenAI 兼容、Responses、Gemini、Anthropic、Azure OpenAI、Ollama 与 Custom 等接口形态，实际可用范围取决于供应商配置与适配器能力。
* 按账号保存 API 配置、快捷短语、提示词模式、风格偏好、项目偏好、避免项和评判标准。
* 结果库支持预览、下载、笔记和继续编辑。

### 3.4 部署与维护

* Windows 本地一键启动与前后端分离开发模式。
* Ubuntu VPS 的 systemd + Nginx + PostgreSQL 部署方案。
* 管理员可检查 GitHub Release 更新状态，并在受控条件下运行服务端更新流程。

## 4. 关键产品约束

* 默认聊天不应隐式调用出图；用户明确表达“生成效果图/画一张”等需求后才进入图像工作流。
* 平面图生成以结构保真为第一优先级。不得因风格要求改变房间用途、墙体、门窗、楼梯、电梯、阳台或家具数量/朝向。
* 用户偏好只有在用户明确点击或确认“记住”后才持久化。
* 多账号之间不得共享聊天历史、结果、配置、偏好或 API Key。
* 生产运行数据应保存在 Git 工作树之外，部署更新不得覆盖用户资产与配置。
* 模型输出与联网检索结果存在不确定性；产品应显示来源、错误和下一步操作，不能把模型成功返回等同于设计质量达标。

## 5. 当前范围外

以下内容不是当前已经承诺完成的产品能力：

* 完整的服务端聊天全文搜索、分页和消息级增量存储。
* 非技术用户可直接安装的桌面 EXE 交付。
* 已接入的模型供应商在所有地区、所有账号下的可用性保证。
* 图像生成结果的自动商业可用性、版权或规范合规保证。
* 多人协作、项目权限层级、审计日志和团队级资产管理。

## 6. 后续需求优先级

### P0: 可发布性与可观测性

* 建立 CI，至少覆盖后端测试、前端构建和关键静态测试。
* 建立版本标签/Release 与部署环境的版本记录，避免“主分支已更新但服务器版本不明”。
* 对登录、更新、生成和存储失败提供可追踪的结构化诊断与用户提示。

### P1: 可控的设计生成闭环

* 把平面图分析结果以可编辑的空间约束卡展示，而不是仅以长文本进入提示词。
* 提供“快速出图”和“质量复核”两种清晰模式；质量复核应保留结构、风格、画质和需求匹配的结果。
* 将评估结论直接转化为“修结构/修家具/修风格/局部改图”的下一步动作。

### P1: 稳定性与数据规模

* 将聊天历史从单个完整 JSON/JSONB payload 逐步演进到会话与消息可分页的数据结构。
* 将基准样例及其平面图资产纳入可复现的版本控制或受控测试数据存储。
* 明确生产环境 Cookie、安全传输、访问频率限制和管理员更新权限的安全策略。

### P2: 体验与协作

* 继续拆分前端状态与页面职责，降低大组件修改风险。
* 增加项目级共享、角色权限、设计版本比较和可导出的设计说明。
* 在结构稳定后再扩展多方案生成、风格模板库和更复杂的局部编辑能力。
