# 项目文档

本目录保存 Attuno 的长期维护文档。历史任务方案和一次性调研仍保留在 `.trellis/tasks/` 与 `attuno-studio/docs/`，但以下三份文件是当前项目层面的导航入口。

| 文档 | 用途 | 更新时机 |
| --- | --- | --- |
| [需求文档](requirements.md) | 产品定位、主流程、已交付能力与需求边界 | 产品范围或用户流程变化时 |
| [技术文档](technical-architecture.md) | 架构、数据流、存储、部署、测试与技术债 | API、数据模型、部署或核心实现变化时 |
| [进度文档](project-status.md) | 当前阶段、Git 同步、交付基线、风险与路线图 | 发布前后、每周例行检查或重大任务完成后 |

## 维护规则

1. 状态类结论必须标明核对日期、命令或数据来源，以及无法实时验证的边界。
2. 已上线/已交付与计划中/技术债必须分开写；不能仅凭 Trellis 任务目录的 `in_progress` 状态判断功能未完成。
3. 新功能在合并前至少更新需求文档和技术文档中的相关章节；发布或部署后更新进度文档。
4. 不把 API Key、数据库口令、用户数据、真实访问令牌或运行日志写入本目录。
