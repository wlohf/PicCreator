## 6. 下一步优化路线图

### P0: 先建立可靠交付闭环

1. 增加 CI：后端测试、前端构建、关键前端静态测试、部署脚本语法检查。
2. 建立版本标签和 Release 规范；部署后记录 commit/tag、数据库状态和 `/api/health` 结果。
3. 核对 VPS 当前版本并通过受控更新同步到计划发布版本。
4. 整理历史 Trellis 任务台账，使任务状态重新具备可信度。

### P1: 提升生成质量和可控性

1. 将平面图分析结果做成可编辑的空间约束卡。
2. 默认展示“快速出图/质量复核”选择，并保存结构化评估。
3. 让评估结果直接生成可执行的修结构、修家具、修风格或局部编辑动作。
4. 将可复现 benchmark 样例和资产纳入版本控制或专用测试数据存储。

### P1: 为数据增长与生产安全做准备

1. 拆分聊天会话与消息存储，增加分页、增量保存和服务端搜索。
2. 在生产环境配置 Secure Cookie、HTTPS、登录限流、CSRF 防护和管理员操作审计。
3. 为数据库迁移、备份、回滚和资产恢复形成演练脚本。

### P2: 降低前端维护成本

1. 从 `App.tsx` 逐步抽离会话、生成、结果库和供应商配置状态。
2. 给跨层流程增加端到端冒烟测试。
3. 在核心流程稳定后再推进团队协作、项目权限、方案版本管理和模板库。
