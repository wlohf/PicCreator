# 统一设置弹窗尺寸与按钮对齐

## Goal

修复设置弹窗中按钮图标与文字视觉不对齐的问题，并让“生成控制”“模型与 API 设置”“高级功能”等设置页使用一致的弹窗尺寸行为，避免切换面板时弹窗有的放大、有的缩小。

## Requirements

* 设置弹窗外框在不同设置页之间保持一致的宽度和高度。
* 弹窗内容区域应在内容超出时内部滚动，而不是改变弹窗整体尺寸。
* “保存配置”“验证分析模型”“验证画图模型”“恢复默认”“启用严格复核”等按钮的图标和文字应垂直居中对齐。
* 保持现有视觉语言、圆角、边框、侧栏导航和文案，不做无关重构。

## Acceptance Criteria

* [ ] 切换“生成控制”“模型与 API”“高级功能”时弹窗外框宽高保持一致。
* [ ] 内容较多的面板在右侧内容区滚动，不撑大弹窗。
* [ ] 设置面板内按钮图标和文字在同一视觉中线。
* [ ] 前端 lint/typecheck 或项目可用的等价检查通过；如无法运行，记录原因。

## Definition of Done

* 代码改动集中在设置弹窗相关前端文件。
* 遵循现有组件和 Tailwind/CSS 写法。
* 不改动后端契约和业务状态逻辑。

## Technical Approach

先定位设置弹窗组件和 className/CSS 样式。优先通过共享按钮 class 或局部容器样式修正对齐；通过固定 modal content 高度、最大高度、grid/flex 子项 min-height 和 overflow 规则统一尺寸。

## Decision (ADR-lite)

**Context**: 当前不同设置页内容高度不同，弹窗容器可能按内容伸缩；按钮内图标与文字可能受 line-height、inline svg 或 padding 差异影响。

**Decision**: 在设置弹窗的统一容器层固定尺寸行为，在内容区域内部滚动；按钮使用 inline-flex/flex、items-center、稳定 gap 和 leading-none/leading-normal 的组合保证对齐。

**Consequences**: 保持实现局部化，减少影响主页面其他按钮；长内容面板需要用户在弹窗内容区滚动。

## Out of Scope

* 不重设计设置页信息架构。
* 不新增配置项或改动 API 保存逻辑。
* 不修改非设置弹窗的按钮样式，除非它们复用同一局部组件。

## Technical Notes

* 用户截图显示“高级功能”弹窗明显更高，“生成控制”较矮，“模型与 API”内容长且可滚动；目标是统一弹窗外框尺寸。
* 前端规范文件目前多数为占位，需遵循现有代码风格。
